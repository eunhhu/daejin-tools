# 도서관 빈자리 시간표

도서관 예약실 상세 화면의 **선택 가능한 시작시간**을 호실별 시간표로 모읍니다.
세미나실·캐럴·소강당, 날짜, 이용 인원으로 좁혀 보고 칸을 누르면 공식 상세 화면으로
이동하거나 종료 시간·사용 목적을 확인한 뒤 **예약 확정**할 수 있습니다.
취소·입실 시작은 공식 앱에서 직접 합니다.

**[사용설명서](USER_GUIDE.md)** · 실행 중인 페이지의 `/manual`에서도 볼 수 있습니다.

## 데이터 의미

- 초록: 원본 `start_time` select에 있는 시작 시간. 이용 가능한 전체 구간, 특정 이용 길이,
  또는 최종 예약 성공을 보장하지 않습니다.
- 회색: 원본에서 선택할 수 없는 시간. 예약 중/휴실/운영시간/계정 제한 중 어느 이유인지는 추정하지 않습니다.
- 물음표: 해당 호실을 파싱하지 못한 상태. 빈자리로 취급하지 않습니다.
- 지난 시각은 캐시 안의 옵션에 남아 있어도 비활성화합니다. 시간대는 `Asia/Seoul`입니다.
- 축의 09:00–20:00은 참고용 표시 범위이며 영업시간 판정이 아닙니다. 원본의 다른 시간도 포함합니다.
- 결과는 연결된 **운영자 계정에 보이는 정보**입니다. 이용자마다 자격이 다를 수 있으므로
  타인의 예약 가능 여부를 보증하지 않습니다.

## 언제 학교에 요청하나

`GET /api/schedule?date=YYYY-MM-DD`를 실제로 받을 때만 조회합니다.
서버 시작, 상태 확인, 정적 HTML, 필터 변경은 학교에 요청하지 않습니다.
페이지 접속·날짜 변경·수동 새로고침 외에 시간표 자동조회는 없습니다.
시간 칸 선택 시 상세·종료 시간 2회를 추가 조회하고, 최종 확정 시에만 공식 내역 조회 →
사전 검사 → 단 한 번 예약 처리 → 공식 내역 확인을 순차 실행합니다. 자동 재제출은 없습니다.

- 날짜별 5분 메모리 캐시, 프로세스 내 단일 잠금으로 동시 접속 요청 합치기
- 새로운 조회 묶음 사이 최소 30초, 프로세스 전체 시간당 최대 6묶음
- 한 묶음: 목록 1회 + 목록에서 확인된 호실별 1회, 순차 요청 사이 0.5초 간격
- HTTP 리다이렉트·401·403·429·연결 실패 시 중단. 자동 재로그인·재시도·keepalive 없음
- 실패 후 5분 재시도 억제. 이전 결과는 최대 30분까지 **이전 시각·경고**와 함께 표시
- 애플리케이션 자체 조회 범위는 한국 시간 기준 오늘부터 7일. 학교의 예약 가능 기간을 뜻하지 않음
- 사람이 시작한 묶음은 탭을 닫더라도 서버에서 유한한 요청을 마칠 수 있음. 다음 묶음은 자동 시작하지 않음

**중요:** 이 제한은 단일 프로세스용입니다. 반드시 `--workers 1`로 실행합니다.
다중 복제·무중단 교체·공개 서비스로 확장하려면 공유 캐시/분산 제한을 먼저 구현해야 합니다.
재시작은 메모리 캐시/한도를 초기화하므로 이를 빈번한 재조회 수단으로 쓰지 않습니다.

## 로컬 실행

저장소 루트에서 실행합니다. 기존 수강 앱을 import하거나 기동하지 않습니다.

```bash
python -m pip install -r apps/library/requirements.txt
# 기존에 승인받아 로그인한 본인의 도서관 세션만 사용합니다.
export DAEJIN_LIBRARY_SESSION_FILE=/absolute/private/path/library-session.json
chmod 600 "$DAEJIN_LIBRARY_SESSION_FILE"
python -m uvicorn apps.library.web:create_app --factory --host 127.0.0.1 --port 18764 --workers 1
```

Windows PowerShell에서는 `export` 대신
`$env:DAEJIN_LIBRARY_SESSION_FILE = 'C:\private\library-session.json'`을 사용하고 파일 ACL을
본인에게 제한합니다. 서버 페이지는 `http://127.0.0.1:18764/`입니다.

세션 파일은 CDP `Storage.getCookies` 형식의 JSON 배열입니다. 각 항목은
`name`, `value`, `domain`, `path` 필드를 사용합니다. 로더는 정확히
`library.daejin.ac.kr` 도메인의 쿠키만 사용하며 다른 사이트 쿠키는 전달하지 않습니다.
실제 세션은 저장소 바깥에 보관합니다. GitHub·클라이언트 JS·API 응답·로그에 넣지 않습니다.

**세션 만료는 남아 있는 운영 제약입니다.** 도서관에서 정상 로그인한 후 운영자가 세션
파일을 갱신해야 합니다. 이 버전은 포털 비밀번호를 저장하거나 자동 로그인하지 않으며,
정해진 주기로 세션을 유지하지 않습니다. 갱신 후 실패 쿨다운이 끝나면 다음 방문 요청에서
새 파일을 읽습니다. 상태 확인(`/healthz`)은 세션 유효성 검사를 하지 않습니다.

이 앱 자체에는 외부 공개용 이용자 인증이 없습니다. **기본은 개인 로컬 사용입니다.**
공개 IP로 바인딩하거나 누구나 사용하는 중계 서버로 배포하지 마세요. 접근 인증,
계정별 데이터 경계, 학교 허용 범위·트래픽 예산을 검토한 뒤 별도 배포해야 합니다.

## 코드와 검증

- `parser.py`: 인라인 JS를 실행하지 않고 허용된 호실 링크·select만 파싱
- `source.py`: 고정 HTTPS origin과 조회 경로 2개만 사용. 예약 실행 경로 없음
- `service.py`: 접속 시 캐시·중복 합치기·요청 한도·오류 처리
- `booking.py`: 2분 예약 준비, 공식 양식 검증, 서버 사전 검사, 단일 제출, 내역 확인과 비공개 중복 방지 기록
- `web.py`: FastAPI, 외부 리소스 없는 정적 UI, no-store/CSP, Host 및 CSRF 검증
- `static/`: 한국어 반응형 시간표, 클라이언트 내부 필터, 접근성 레이블

```bash
python -m pip install -e '.[dev]' -r apps/library/requirements.txt -r apps/sugang/requirements-web.txt
python -m pytest -q -W error
python -m ruff check src tests apps/library
npm ci
npm test
```

Node.js 22 이상은 DOM 테스트에만 필요합니다. 실제 앱은 Node 런타임·프론트엔드 빌드·CDN이
필요하지 않습니다. Python 테스트는 소켓 차단 상태에서 명시적인 합성 HTML과 MockTransport를
사용하고, 브라우저 테스트 역시 합성 테스트 응답만 사용합니다. CI는 학교에 접속하지 않습니다.
실제 계정으로 수집한 HTML·개인 식별자·쿠키·실시간 예약 데이터는 테스트 fixture로 커밋하지 않습니다.
개발 중 실제 신규 예약·취소는 하지 않았으며, 최종 학교 예약 성공은 아직 실사용 검증 범위입니다.

예약 준비와 확정 확인은 각각 시간당 12회로 제한합니다. 중복 방지 파일은 세션 파일 옆
`library-booking-state.json`이며 단일 운영자 전용입니다. 서버 재시작으로도 불명확한 제출을 재전송하지 않습니다.
