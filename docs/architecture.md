# Repository architecture

## 결정: 기능별 앱 + 작은 공통 Python 패키지

- `apps/<feature>/`: 기능의 진입점, 비즈니스 로직, UI, 전용 리소스와 의존성.
- `src/daejin_tools/`: 앱에 종속되지 않는 공통 Python 코드.
- `tests/<feature>/`: 기능 단위 테스트. 루트 테스트는 패키지·저장소 경계를 확인.
- `deploy/<feature>/`: 배포 참고 파일. 저장만으로 설치나 서비스 변경을 수행하지 않음.
- `docs/`: 여러 기능에 걸치는 설계와 마이그레이션 기록.

의존성 방향은 **앱 → 공통 패키지**입니다. 공통 패키지는 앱을 import하지 않으며
앱끼리 직접 의존하지 않습니다. 공통 코드가 실제로 생기기 전까지 추상 클래스,
플러그인 레지스트리, 범용 인증 관리자 같은 계층을 미리 만들지 않습니다.

새 학사 도구의 프레임워크는 아직 정하지 않았습니다. 기존 Python 코드 때문에
향후 웹 UI까지 특정 프레임워크를 강제하지 않습니다. 독립 manifest를 둔 앱을 추가할 수 있습니다.

## 수강 레거시 경계

기존 Python 파일은 내용 변경 없이 `apps/sugang/`으로 이동했습니다.
설정과 정적 리소스도 같이 이동하여 `__file__` 기반 경로를 보존합니다.
운영용 설정·캐시·키는 자동 이동하지 않습니다.

`web_observer`와 `push_manager`는 import 시 설정·키 파일에 접근하므로
공통 패키지에 포함하지 않습니다. 테스트 전용 임시 복사본만 로드하며
애플리케이션 lifespan이나 백그라운드 감시는 실행하지 않습니다.

## 테스트와 CI

- 기존 회귀 테스트는 임시 설정·임시 키만 사용합니다.
- pytest는 수집 단계부터 네트워크 소켓을 차단합니다.
- 테스트가 사용할 HTML과 응답은 명시적인 테스트 fixture입니다.
- 루트 설치는 수강 의존성을 자동으로 끌어오지 않습니다.
- CI는 공통 wheel을 별도 가상환경에 설치하여 소스 경로 없이 import되는지 확인합니다.
- 수강 GUI 네이티브 실행·실제 학교 연동은 이 CI의 검증 범위가 아닙니다.
